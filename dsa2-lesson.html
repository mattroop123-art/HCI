Topic 1 of 3

Linear probing

A hash function chooses a starting slot for a key. When two keys choose the same slot, linear probing resolves the collision by examining successive slots in the same array until it finds an available location. With capacity m, the probe sequence is (h(key) + i) mod m for i = 0, 1, 2, and so on. The modulo wraps the search from the end of the array back to its beginning.

Consider a table with seven slots and h(k) = k mod 7. Insert 10 into slot 3. Key 17 also hashes to 3, so it checks 3, finds 10, and moves to empty slot 4. Key 24 checks 3 and 4, then occupies slot 5. These keys still have distinct identities; sharing a starting slot does not make them equal.

Lookup must follow the same probe sequence as insertion. To find 24, start at slot 3 and compare each stored key until reaching slot 5. A never-used empty slot means the key is absent, because insertion would have stopped there. Search must also stop after at most m probes so a full table cannot cause an infinite loop.

Topic 2 of 3

Clustering

Linear probing tends to create adjacent runs of occupied slots called primary clusters. A collision at any point within a run sends a new key toward the end of that run. Adding it there makes the run larger, so even more starting locations may lead into it. Neighboring runs can eventually merge.

In the previous example, slots 3, 4, and 5 form a cluster. Suppose key 11 hashes to slot 4. It checks 4 and 5 before entering slot 6, even though its hash differs from the keys starting at 3. The longer cluster now increases the work needed for other insertions and unsuccessful searches that encounter it.

The load factor is the number of stored entries divided by capacity. As this fraction approaches one, empty slots become scarce and probing generally becomes more expensive. Expected constant-time operations depend on suitable hashing assumptions and keeping enough free space; a worst-case lookup can still inspect the entire table.

Resizing allocates a larger table and reinserts live keys using the new capacity. Copying each entry into its old array index would be incorrect because the hash-to-slot mapping may change. Alternative collision strategies can change clustering behavior, but they introduce their own constraints and implementation choices.

Topic 3 of 3

Tombstones

Deletion must preserve the evidence that a probe sequence continues beyond a slot. If we delete 17 from slot 4 and mark that slot as never used, a later search for 24 would stop at 4 and incorrectly report that 24 is absent, even though it remains in slot 5.

A tombstone marks a slot as deleted rather than never used. Lookup skips the tombstone and continues probing. Insertion may reuse it, but in a map that updates existing keys, it must first check whether the key already exists farther along the probe sequence. Otherwise it could create two entries for the same key.

A careful insertion remembers the first tombstone it encounters, continues until it finds the existing key or a never-used empty slot, and then either updates that key or inserts into the remembered tombstone. A bounded full-table scan also needs to handle the case where there is no never-used slot but a tombstone is available.

Tombstones accumulate and can lengthen searches even when there are few live entries. Rehashing live keys into a fresh table removes them. An implementation should therefore consider deleted slots as well as live entries when deciding whether to rebuild.
